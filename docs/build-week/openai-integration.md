# OpenAI Integration

Phase 4A uses Responses with strict Zod-backed Structured Outputs, `store: false`, explicit reasoning effort, abort timeouts, stable safety identifiers, and no model-selected tools. Prompts are `trailie-change-analysis-v1` and `trailie-itinerary-revision-v1`. Provider IDs and usage stay private.

Verified on **July 13, 2026** against official OpenAI documentation and the official `openai/openai-node` repository.

## Verified selections

- SDK: exact `openai@6.46.0`, the current release verified from the official Node SDK releases.
- Conversation model: `gpt-5.6-terra`. OpenAI describes Terra as the balanced GPT-5.6 model for demanding everyday workloads.
- Rare escalation model: `gpt-5.6-sol`. OpenAI describes Sol as the frontier GPT-5.6 model. The generic `gpt-5.6` alias routes to Sol, so Trailie uses explicit model IDs instead of that alias.
- Not invoked in Phase 2A: `gpt-5.6-luna`, the high-volume tier. There are no background model calls.
- API: Responses API through `client.responses.stream(...)`.
- Reasoning: `{ effort: "low" }`. The current GPT-5.6 guide lists `none`, `low`, `medium`, `high`, `xhigh`, and `max`; Trailie uses only `low`.
- Structured output: strict JSON Schema generated by `zodTextFormat(...)` in `text.format`, followed by local Zod validation of `response.output_parsed`.
- Streaming: the SDK Responses stream. Trailie consumes only `response.output_text.delta`, extracts the safe `body` string from the structured JSON stream, and waits for the final parsed response before persistence.
- Retention: `store: false` on every OpenAI request. OpenAI documents that Responses otherwise have application-state retention by default, while Zero Data Retention forces `store` false.
- Safety identifier: `safety_identifier` is an HMAC-SHA-256 digest of the authenticated Auth user ID under `OPENAI_SAFETY_HMAC_SECRET`. Raw IDs, email, display name, invite data, and the HMAC input are not sent in this field.
- Cancellation: the request `AbortSignal` is passed to the SDK request options.
- Timeout/retry: 30-second application timeout and SDK `maxRetries: 2`; authentication, permission, and invalid-request errors are not retried by application code.

## Deliberate exclusions and clarified assumptions

Earlier architecture notes described generic background, conversation, and planning tiers. Phase 2A adds only `OPENAI_MODEL_CONVERSATION` and `OPENAI_MODEL_FLAGSHIP`, because only those values are used. There is no `OPENAI_MODEL_BACKGROUND` or planning-model variable, no invented reasoning mode, no context-setting field, no model-selected routing, and no undocumented alias. The documented GPT-5.6 Pro behavior and the Luna tier are not used.

Strict structured output and streaming are combined through the current SDK. Because deltas contain partial JSON rather than display-ready text, Trailie extracts only the envelope's `body` value for the invoking client's optimistic stream, then validates the final complete envelope and persists only its body. Partial fragments, raw payloads, prompts, reasoning, usage, and request metadata are never persisted as chat messages or streamed to participants.

## Phase 3A verification — 2026-07-13

Official OpenAI model and API documentation was rechecked before implementation. Exact `gpt-5.6-sol` supports the Responses API, Structured Outputs, and high reasoning effort, with a 1,050,000-token context window and 128,000 maximum model output tokens. Trailie intentionally bounds the request much lower: strict `text.format` generated through `zodTextFormat`, `reasoning: { effort: "high" }`, `max_output_tokens: 3000`, `store: false`, no tools, a safety identifier, and an application abort signal under the pinned `openai@6.46.0` SDK. [Sol model](https://developers.openai.com/api/docs/models/gpt-5.6-sol), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [Reasoning](https://developers.openai.com/api/docs/guides/reasoning), [Responses](https://developers.openai.com/api/reference/resources/responses/methods/create)

Usage is read from final response input, cached-input, output, reasoning-output, and total-token fields; response/request IDs, latency, versions, attempts, and safe errors are private. Full prompts, raw responses, duplicated transcripts, and hidden reasoning are not retained. The provider call is synchronous inside a post-response Next.js `after()` task because the application must validate readiness and atomically publish one immutable version. OpenAI background mode and Batch were considered but not used: background mode conflicts with the store-disabled retention boundary, while Batch's asynchronous file lifecycle does not fit an interactive crew review.

Planning prompt: `trailie-planning-summary-v1`. Planning schema: `1`. Live planning smoke: **not run; no live success claimed**.

## Phase 3B verification — 2026-07-13

Official OpenAI documentation was reverified before locking itinerary implementation. Exact `gpt-5.6-sol` supports Responses, Structured Outputs, function calling, streaming, and `high`/`xhigh` reasoning. Trailie uses `high`, which is sufficient for multi-constraint scheduling while avoiding the additional latency/cost of `xhigh`. The pinned SDK is `openai@6.46.0`.

The implemented call is `client.responses.parse` with `zodTextFormat(itinerarySchema, "trailie_itinerary")`, which emits strict Responses `text.format` JSON Schema. It sets `store: false`, `max_output_tokens: 12000`, `reasoning: { effort: "high" }`, `safety_identifier`, a 90-second SDK timeout, and an abort signal. The response is parsed again with the shared strict Zod schema. At most one regeneration is allowed for a structurally invalid response; later schedule repair is separately capped at one.

Itinerary calls are synchronous and non-streaming because no draft is shown before deterministic validation. Official typed SSE streaming was considered for UI progress, but application-owned persisted stages are safer and reconnectable. Function calling and Programmatic Tool Calling were considered but deferred: the worker invokes bounded provider-neutral travel adapters directly, so the model cannot select tools, browse, loop, or publish. Background mode and Batch remain deferred because `store: false` and interactive publication/recovery are required.

Usage fields retained privately are input, cached input, output, reasoning output, total tokens, response/request IDs, attempt, latency, and safe error. Raw prompts, raw responses, hidden reasoning, and provider errors are not stored. Request cancellation uses the SDK signal; timeout/rate/unavailable errors map to safe application codes.
