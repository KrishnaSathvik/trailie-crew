# OpenAI Integration

Verified on **July 13, 2026** against official OpenAI documentation and the official `openai/openai-node` repository.

## Verified selections

- SDK: exact `openai@6.46.0`, the current release verified from the official Node SDK releases.
- Conversation model: `gpt-5.6-terra`. OpenAI describes Terra as the balanced GPT-5.6 model for demanding everyday workloads.
- Rare escalation model: `gpt-5.6-sol`. OpenAI describes Sol as the frontier GPT-5.6 model. The generic `gpt-5.6` alias routes to Sol, so Trailie uses explicit model IDs instead of that alias.
- Not invoked in Phase 2A: `gpt-5.6-luna`, the high-volume tier. There are no background model calls.
- API: Responses API through `client.responses.stream(...)`.
- Reasoning: `{ effort: "low" }`. The current GPT-5.6 guide lists `none`, `low`, `medium`, `high`, `xhigh`, and `max`; Trailie uses only `low`.
- Structured output: strict JSON Schema generated by `zodTextFormat(...)` in `text.format`, followed by local Zod validation of `response.output_parsed`.
- Streaming: the SDK Responses stream. Trailie consumes only `response.output_text.delta`, extracts the safe `body` string from the structured JSON stream, and waits for the final parsed response before persistence.
- Retention: `store: false` on every OpenAI request. OpenAI documents that Responses otherwise have application-state retention by default, while Zero Data Retention forces `store` false.
- Safety identifier: `safety_identifier` is an HMAC-SHA-256 digest of the authenticated Auth user ID under `OPENAI_SAFETY_HMAC_SECRET`. Raw IDs, email, display name, invite data, and the HMAC input are not sent in this field.
- Cancellation: the request `AbortSignal` is passed to the SDK request options.
- Timeout/retry: 30-second application timeout and SDK `maxRetries: 2`; authentication, permission, and invalid-request errors are not retried by application code.

The documented stream lifecycle includes `response.created`, `response.output_text.delta`, `response.completed`, and error events. Trailie does not forward raw provider events. Usage is read only from the final response fields `input_tokens`, `input_tokens_details.cached_tokens`, `output_tokens`, `output_tokens_details.reasoning_tokens`, and `total_tokens`. Provider response ID and the SDK `_request_id` are retained only in private operations records.

## Deliberate exclusions and clarified assumptions

Earlier architecture notes described generic background, conversation, and planning tiers. Phase 2A adds only `OPENAI_MODEL_CONVERSATION` and `OPENAI_MODEL_FLAGSHIP`, because only those values are used. There is no `OPENAI_MODEL_BACKGROUND` or planning-model variable, no invented reasoning mode, no context-setting field, no model-selected routing, and no undocumented alias. The documented GPT-5.6 Pro behavior and the Luna tier are not used.

Strict structured output and streaming are combined through the current SDK. Because deltas contain partial JSON rather than display-ready text, Trailie extracts only the envelope's `body` value for the invoking client's optimistic stream, then validates the final complete envelope and persists only its body. Partial fragments, raw payloads, prompts, reasoning, usage, and request metadata are never persisted as chat messages or streamed to participants.

## Smoke test

`pnpm test:openai:smoke` skips cleanly without `OPENAI_API_KEY`. With a key, it sends one tiny stored-disabled structured request to `OPENAI_MODEL_CONVERSATION` (default Terra), validates the parsed result, and prints no secret or user data. Expected cost is the provider charge for one very small request (roughly one short input and at most 80 output tokens). It does not run in normal tests or CI.

## Phase 2B verification — 2026-07-13

Official documentation confirms `gpt-5.6-luna` is the lightweight cost-sensitive/high-volume GPT-5.6 model, roughly corresponding to the earlier nano tier. Memory extraction uses the Responses API, strict `text.format` JSON Schema through the official Node SDK Zod helper, `reasoning.effort: "none"`, `store: false`, no tools, an 800-token output cap, `safety_identifier`, SDK timeout, and an abort signal. [Model](https://developers.openai.com/api/docs/models/gpt-5.6-luna), [Structured Outputs](https://developers.openai.com/api/docs/guides/migrate-to-responses#6-update-structured-outputs-definitions), [GPT-5.6 reasoning](https://developers.openai.com/api/docs/guides/latest-model)

The pinned SDK is `openai@6.46.0`. Compatibility is proven locally by typecheck and request-contract tests. Background mode is not used because it requires stored response state; Batch is not used because its file/24-hour lifecycle does not match per-message memory. The request instead runs synchronously inside a Next.js post-response worker. [Background](https://developers.openai.com/api/docs/guides/background), [Batch](https://developers.openai.com/api/docs/guides/batch), [retention](https://developers.openai.com/api/docs/guides/your-data#v1responses)
